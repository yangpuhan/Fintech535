The cached pull

Everything the published site shows was pulled once from LSEG and baked into book.js. GitHub Pages serves files and nothing else, so the backtest cannot be re-run in the browser and the tape cannot be refreshed from it.

Chain resolution

Synthetic RICs name contracts that may never have listed. Requests go out in batches and split on failure, so one dead name costs a bisect rather than the whole batch. This is what resolved, per expiry.

Running it locally

The fetcher is a tool, not part of the published site. It needs LSEG Workspace running and an app key in lseg-data.config.json, which is gitignored and never leaves the machine.

python -m covered_call.fetch    # LSEG  ->  covered_call/data.pkl
python -m covered_call.build    # data.pkl  ->  docs/book.js

python covered_call/local_server.py
# http://127.0.0.1:8765/data.html
Why the published site has no live connection. An app key that reaches a market data entitlement is a credential. Publishing a page that could use one would mean either shipping the key to every visitor or standing up a proxy that spends the entitlement on their behalf. Neither is something a coursework site should do, so the boundary is drawn at the pickle: the pull happens on a machine that is entitled, and what gets published is the result.
