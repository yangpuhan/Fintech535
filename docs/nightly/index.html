AAPL against the market, redrawn every weeknight

How this page updates

  1. Trigger. The Nightly LSEG refresh workflow (.github/workflows/nightly.yml) runs at 08:00 UTC Tuesday to Saturday (3 a.m. in New York, so every weekday session is covered), or whenever Run workflow is pressed on that page.
  2. Query. On a GitHub-hosted Ubuntu runner, nightly/refresh.py opens an LSEG platform session from three repository secrets and makes two get_history requests: daily closes for AAPL.O and SPY, about fifteen months of each.
  3. Write. It draws the Plotly figure to docs/nightly/aapl-vol.html and the numbers in the tiles to docs/nightly/meta.json.
  4. Publish. The workflow commits those two files to main. GitHub Pages republishes docs/, and the frame above loads the new chart.

If LSEG refuses the login or returns no data, the script stops before it writes anything. The site keeps the last good chart, and the run shows red on the Actions page. The usual cause is the clock: this LSEG account allows one sign-in at a time, and the job does not take over a Workspace session that is open, so it runs in the small hours, when Workspace is normally closed.

Definitions

Realised volatility is the standard deviation of daily log returns, ln(Pt/Pt−1), over the last 21 sessions, times √252, in percent. Only completed sessions count: a run before 16:15 New York time drops that day's still-forming bar. Prices are LSEG TRDPRC_1 daily closes, not adjusted for dividends.

Why SPY and not the VIX. The natural yardstick for an option seller is implied volatility, but this LSEG account is not permissioned for CBOE indices (.VIX comes back "User has no permission"). SPY's realised volatility is how much the market itself moved. The gap between the two lines is how much more AAPL moves than the market, from its beta and its own news together. It is not a variance premium, which would need AAPL's implied volatility.
